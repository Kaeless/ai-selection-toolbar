# AI 划词工具栏：已确认需求方案

> 版本：v0.1 ｜整理日期：2026-09-24 ｜状态：需求基线，尚未进入开发

## 1. 产品目标

开发一款面向其他用户发布的 Windows 桌面工具。用户在受支持程序中选中文字后，可在选区附近打开悬浮工具栏，使用可配置的 AI 接口解释、翻译或提问，并把有价值的解释保存为本地 Markdown 学习笔记。

附图仅作为工具栏交互参考；本方案以下述已确认的功能为准。

## 2. 支持范围

| 项目 | 已确认要求 |
| --- | --- |
| 操作系统 | Windows 7 SP1 64 位至 Windows 11；不要求 32 位 Windows |
| 首版验收程序 | Chrome、Edge、Firefox、Microsoft Word、PowerPoint、Adobe Acrobat Reader |
| PDF 文本 | 处理阅读器中原本可选中的文字；首版不做扫描件 OCR |
| 发布形式 | 安装包和免安装压缩包均提供 |

“支持程序”是对工具栏在该程序中提取选中文本并展示的验收要求。各程序在 Windows 7 上可运行的版本，与新系统上的版本可能不同；测试矩阵应明确记录实际版本。尤其 Chrome 与 Edge 的 Windows 7 最后兼容主版本均为 109，Firefox 为 115 ESR。此事实不改变工具自身的 Windows 7 支持目标，但限制了 Windows 7 上可测试的浏览器版本。[Chrome 官方说明](https://support.google.com/chrome/thread/185534985/sunsetting-support-for-windows-7-8-8-1-and-windows-server-2012-and-2012-r2-in-early-2023?hl=en) · [Edge 官方说明](https://learn.microsoft.com/en-us/lifecycle/products/microsoft-edge) · [Firefox 官方说明](https://support.mozilla.org/en-US/kb/firefox-users-windows-7-8-and-81-moving-extended-support)

## 3. 划词与悬浮工具栏

1. 用户通过鼠标选中文字并松开鼠标后，在选区附近显示悬浮工具栏。
2. 用户通过键盘选中文字时，可用快捷键主动唤出工具栏；键盘选中本身不自动弹出。
3. 工具栏提供 **解释、翻译、提问**。不提供截图中的“复制”动作。
4. 点击任一 AI 动作后，结果在选区附近的可滚动面板中显示，并以流式方式逐步呈现；面板提供“停止生成”。
5. 关闭结果面板后，已保存的结果可从历史记录找回。
6. 用户可在设置中排除指定程序。被排除程序内不弹出工具栏、不读取选中文本，也不创建记录。

## 4. AI 接口与请求

1. 设置项为 **API 地址、API 密钥、模型名称**；采用兼容 OpenAI API 的请求与响应格式。
2. API 地址允许填写本机地址，以接入提供兼容接口的本地服务。
3. 仅在用户点击解释、翻译或提问后，才把所选文本发送给已配置的接口。
4. 未配置 API 时，用户仍可进入设置和历史记录；点击 AI 动作时提示完成配置，不发出请求。
5. 翻译默认目标语言为简体中文，用户可在设置中更改。

## 5. 学习笔记

1. “解释”先展示结果；用户点击 **做笔记** 后进入保存流程，不因解释完成而自动写入。
2. 保存前允许编辑笔记内容。每条笔记至少包括时间、来源、选中原文、解释结果。
3. 笔记保存在用户本地的 Markdown 文件中。同一来源文档每天使用一个文件，多次保存向该文件追加条目。
4. 文件名格式以 `日期_来源文件名_学习.md` 为例，例如 `2026-09-24_课程讲义_学习.md`；实际保存目录由后续设计确定，并应允许用户查看或配置。
5. 网页使用页面标题或网址作为来源；Word、PPT、PDF 优先使用文件名。取不到来源时使用程序名，再取不到则使用“未命名”。
6. 同一条解释重复保存时给出提示，避免无意重复添加。

## 6. 本地历史记录

1. 使用本地数据库保存历史，供用户追溯。
2. 每条历史保存时间、动作类型、选中原文、提问内容（如有）、AI 回复、来源程序与来源文件或页面。
3. 提供历史搜索、单条删除、清空全部记录。
4. 关闭结果面板不删除历史记录。被排除程序中的文本不进入历史记录。

## 7. 安装与运行设置

1. 提供开机启动开关，默认关闭。
2. 提供检查更新开关，默认关闭；启用后只提示可用更新，不自动安装。
3. 安装包与免安装版应能使用相同的功能范围。

## 8. 首版验收场景

| 场景 | 预期结果 |
| --- | --- |
| 在验收程序中用鼠标选中可选文本并松开 | 工具栏在选区附近出现 |
| 用键盘选中文字后按唤出快捷键 | 工具栏出现；仅键盘选中时不自动出现 |
| 点击解释、翻译或提问 | 按配置向 API 发起请求，结果流式显示，可停止生成 |
| 点击做笔记并确认 | 可编辑后写入当天、该来源的 Markdown 文件；重复保存给出提示 |
| 打开历史 | 可搜索、查看、删除单条或清空全部记录 |
| 在被排除程序中选中文字 | 不弹工具栏，不读取文本，不留历史 |
| 未配置 API 时点击 AI 动作 | 引导配置，不发出请求 |
| 在 Windows 7 SP1 64 位与 Windows 11 上安装或运行 | 安装版和免安装版均可启动并完成对应程序的核心场景测试 |

## 9. 尚待技术验证或后续确定

以下内容没有在需求访谈中确定，不作为本版已确认功能：

- 各目标程序及版本提取选中文本、获取选区位置与来源名称的具体方式，尤其跨浏览器、Office 和 PDF 阅读器的差异。
- Windows 7 可用的桌面框架、运行时、打包和更新方案；需先做兼容性原型。
- 快捷键的具体组合、工具栏尺寸与视觉样式、窗口失焦后的关闭规则。
- API 密钥在本机的保存方式、请求超时与失败重试规则、本地接口的认证方式。
- 笔记与数据库的默认保存路径、备份与迁移方式；安装版与免安装版的数据位置差异。
- 是否为以后加入 OCR、朗读、AI 搜索、多接口切换等功能。

## 10. 开发前的验证顺序

1. 先验证 Windows 7 SP1 64 位上的技术栈与基础悬浮窗能运行。
2. 再逐一验证六类目标程序中的选中文本、选区位置和来源获取。
3. 在以上可行后实现 API、历史、笔记、设置和打包。
4. 按第 8 节的场景完成跨系统、跨程序验收。
